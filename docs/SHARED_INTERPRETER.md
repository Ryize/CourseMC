# Совместный «Твой Интерпретатор»

У каждого онлайн-занятия один отдельный Python-документ. Он не связан с личным
черновиком браузера и не изменяет исходные файлы домашних заданий.

## Как пользоваться

1. Преподаватель и ученики входят в онлайн-комнату, включая допуск из зала ожидания.
2. Преподаватель нажимает **Код** на нижней панели звонка. Открывается существующий
   «Твой Интерпретатор» внутри комнаты, звук звонка продолжает работать.
3. Ученики нажимают **Код** у себя. Пока преподаватель не открыл документ, редактор
   ждёт его автоматически. Перезагружать страницу не нужно.
4. Ученики по умолчанию только смотрят общий код, но могут самостоятельно его
   запускать. В **Доступ к редактированию** преподаватель отмечает нужных участников.
   Правки и курсоры синхронизируются; одновременно писать могут несколько человек.
5. **Запустить код** / `Ctrl/⌘ + Enter` выполняет текущий общий код в браузере
   нажавшего кнопку. Консоль и `input()` личные. Полученный от других код никогда
   не запускается автоматически и не выполняется на Django-сервере.
6. **Сохранить версию созвона** создаёт отдельный неизменяемый `.py`-снимок с названием.
   Он появляется в версиях редактора и блоке **Код занятия** на странице созвона.
7. **Прикрепить .py к уроку программы** в редакторе: выберите урок и группу, затем
   нажмите **Прикрепить .py к уроку**. После синхронизации сохраняется копия текущего
   кода. Прикрепление доступно только для группового созвона и его участвующих групп
   ведущего. В открытых созвонах эта форма не показывается; версии созвона сохранять
   можно. Уроки берутся из направлений обучающихся учеников группы.
   В поле названия над формой можно задать название версии.
8. Ранее сохранённую версию можно прикрепить под звонком: **Код занятия → Прикрепить
   код к уроку программы → Версия созвона → Урок программы и группа**. Можно сохранить
   материалы и после завершения созвона.
9. Закрытие панели не завершает звонок. Можно открыть редактор в отдельной вкладке.
   После завершения занятия общий код доступен только для просмотра/локального запуска.

Версии созвона доступны преподавателю и допущенным участникам. Открытый урок не
делает документ публичным: гости сначала должны получить допуск; удалённые участники
теряют доступ к редактору и версиям созвона.

**Прикреплённый файл** — отдельный материал для группы. В «Расписании» под выбранным
уроком появляется блок **Код к уроку → Скачать .py**. Его могут скачать преподаватель
и действующие ученики выбранной группы с доступом к этому уроку программы, даже если
они не участвовали в созвоне. Гости открытого созвона и другие группы этого материала
не получают. Новые правки общего кода и новые версии не меняют уже прикреплённый файл.
Повторная отправка одной версии в тот же урок и группу не дублирует материал.

## Сохранение и восстановление

Принятые правки сохраняются автоматически в SQLite/PostgreSQL как документ CRDT.
Yjs и pycrdt объединяют изменения; повтор запроса после сбоя не дублирует вставку.
Синхронизация работает через Django на том же сервере, без Redis и дополнительного
сервиса. Обычно новая правка отправляется через 100–150 мс; другие редакторы
проверяют обновления приблизительно раз в секунду. Для текущей небольшой нагрузки.

При недоступном сервере редактирование блокируется, неподтверждённые правки
остаются в памяти вкладки и повторяются после восстановления связи. Если сервер
отклонит их (отзыв доступа, завершение занятия, превышение лимита), можно скачать
**несохранённые правки**, а редактор вернётся к принятой версии. До подтверждения
сохранения не закрывайте вкладку. Несохранённый буфер не переживает аварийный выход
браузера. Лимиты: код 20 000 UTF-16 символов, обновление 96 KiB, состояние 512 KiB.

Права проверяются сервером на каждом запросе. Нахождение в медиакомнате проверяется
при открытии и затем с короткой 8-секундной арендой; удаление/отзыв прав проверяются
без этой задержки. Для большего числа одновременно открытых редакторов стоит
заменить HTTP-опрос WebSocket-транспортом, не меняя формат документа.

## Запуск / обновление

В существующем окружении проекта:

```sh
source .venv/bin/activate
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py runserver 127.0.0.1:8000
```

Перед миграцией существующей базы сделайте согласованный SQLite-бэкап. На сервере
обычная сборка Docker устанавливает `pycrdt` из `requirements.txt`, а entrypoint
применяет миграции `py_interpreter.0001_initial` и `0002_sharedcodeattachment`. Нужна пересборка образа, не только
перезапуск контейнера. Медиасервер для звонка запускается прежним способом.

Yjs 13.6.33 уже собран в локальный статический файл, внешний сервер синхронизации
не используется. Его повторная сборка (только при изменении браузерных зависимостей):

```sh
cd py_interpreter/frontend
npm ci
npm run build
```

Лицензия находится рядом с собранным файлом. Ace и Python/Pyodide продолжают
загружаться прежним способом. Клиент без Ace использует простой текстовый редактор.

## Проверки

```sh
python manage.py test py_interpreter live_lessons --noinput
node --test py_interpreter/tests_js/*.test.cjs live_lessons/tests_js/*.test.cjs
```

Проверяются доступы групп и гостей, ожидание/удаление, выдача/отзыв прав, совместные
правки, повтор доставки, курсоры, локальная отмена своих правок, сохранённые версии,
лимиты и совместимость реального браузерного Yjs с серверным pycrdt.
