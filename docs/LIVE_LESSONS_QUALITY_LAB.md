# Лаборатория качества связи

Это стенд первого блока, а не готовый сервис уроков. Он доступен авторизованному пользователю только при `DJANGO_DEBUG=True`, не создаёт моделей или миграций и не меняет рабочую базу. Токены выдаются только локальным LiveKit в режиме разработки; их нельзя использовать на публичном сервере.

## Запуск локально

Если Docker и Colima уже установлены, из корня проекта можно запустить весь локальный стенд одной командой: `bash scripts/run_live_lessons_local.sh`. Скрипт поднимет LiveKit с тестовыми ключами и запустит Django с совпадающими настройками. Порт 8000 должен быть свободен; если он занят, скрипт не останавливает чужой процесс.

Ниже — те же шаги по отдельности, если нужен ручной запуск или диагностика.

1. Установите и запустите LiveKit по [официальной инструкции](https://docs.livekit.io/transport/self-hosting/local/): `livekit-server --dev`. Он слушает `ws://127.0.0.1:7880` и использует только локальные тестовые ключи. Если LiveKit не установлен, но уже есть Docker и Colima, можно поднять отдельный локальный контейнер:

   ```sh
   colima start
   docker run -d --rm --name coursemc-livekit-local \
     -p 127.0.0.1:7880:7880/tcp \
     -p 127.0.0.1:7881:7881/tcp \
     -p 127.0.0.1:7882:7882/udp \
     livekit/livekit-server:v1.13.7 \
     --dev --bind 0.0.0.0 --node-ip 127.0.0.1 --udp-port 7882
   ```

   Этот контейнер подходит только для проверки в браузерах **на том же компьютере**: он рекламирует `127.0.0.1` как адрес для медиапотока. Другим устройствам и реальным ученикам такая ссылка не подойдёт. Для остановки: `docker stop coursemc-livekit-local`.
2. В другом терминале из корня проекта запустите Django в режиме разработки с теми же локальными ключами:

   ```sh
   LIVEKIT_URL=ws://127.0.0.1:7880 \
   LIVEKIT_API_KEY=devkey \
   LIVEKIT_API_SECRET=secret \
   DJANGO_DEBUG=True \
   .venv/bin/python manage.py runserver 127.0.0.1:8000
   ```

   Для создания урока через интерфейс нужна актуальная локальная база с миграциями `live_lessons`. Перед миграцией сохраните копии `db.sqlite3` и приватных вложений; рабочую серверную базу здесь не используйте.
3. Создайте пару токенов для одной комнаты: `DJANGO_DEBUG=True .venv/bin/python manage.py live_lesson_lab_tokens`. Каждый токен действует 30 минут. Не отправляйте токены в чат и не вставляйте их в URL страницы.
4. Откройте `/live-lessons/quality-lab/` в двух браузерных профилях, войдите в CourseMC в обоих. Вставьте адрес LiveKit и **разные** токены из одной команды. Нажмите «Подключиться».
5. По очереди включите микрофон, камеру и экран; проверьте звук и читаемость кода на другом участнике. Для экранной демонстрации сравните профили «Чёткий текст», «Плавное видео» и «Экономия». Для смены профиля остановите и начните демонстрацию заново.
6. Скачайте технический отчёт с обоих браузеров и запишите субъективные наблюдения. Отчёт не включает токен, голос и содержимое экрана. Он хранится в памяти страницы до скачивания, максимум 1800 последних измерений.

Для захвата экрана нужен HTTPS или localhost; браузер обязательно спросит, каким экраном делиться. Выбранный профиль — желаемые ограничения, фактическая частота кадров и размер показаны в панели измерений и могут отличаться. В некоторых браузерах системный звук экрана недоступен. Если звук второго участника заблокирован автозапуском, нажмите «Включить звук».

## Матрица замеров

Пройдите каждую проверку на реальной сети, а не только на одном компьютере:

| Сценарий | Что записать |
| --- | --- |
| Два участника, отдельные сети | Разборчивость речи, задержку по ощущениям, обрывы, стабильность камеры |
| Экран с IDE и мелким кодом | Минимальный читаемый размер шрифта у ученика, фактическое разрешение/частоту |
| Быстрое движение или видео на экране | Плавность и влияние на качество голоса |
| Ограниченная/нестабильная сеть | Время восстановления, потери пакетов, необходимость «Экономии» |
| Повторный вход и отмена разрешения | Понятность ошибок и восстановление комнаты |

Два браузера на одной машине проверяют только базовую работоспособность, а не качество реального урока. Перед промышленным использованием нужен отдельный защищённый стенд с HTTPS, сетевыми портами и TURN по [руководству развёртывания LiveKit](https://docs.livekit.io/transport/self-hosting/deployment/). Локальные тестовые ключи туда не переносятся.
